# Аппаратная часть

## Плата

Устройство: AJAZZ AKP153R. Маркировка процессора: ARX2902 Q2303. Приложение собирается для ARMv7-M, Thumb, без аппаратных операций с плавающей точкой.

USB работает через опрос MUSB. Прерывания в текущей реализации отключены. `board_service()` обслуживает watchdog, клавиши и USB, в том числе во время ожиданий дисплея.

## Память приложения

| Область | Начало | Размер |
| --- | --- | --- |
| Приложение во flash | `0x08004000` | 96 496 байт |
| RAM приложения | `0x20000000` | 128 KiB |
| Резерв стека | `0x2001E000` | 8 KiB |
| Начальный SP | `0x20020000` | Значение первого вектора |

Эти диапазоны задают контракт сборки. Они не являются измерением полной физической ёмкости памяти процессора. Загрузчик расположен вне области приложения; образ не включает его.

Таблица содержит 80 векторов, занимает 320 байт и начинается с базы приложения. ELF-проверка контролирует Thumb-адреса обработчиков, непересечение load-сегментов, границы flash и RAM. Linker отдельно проверяет отсутствие пересечения BSS и стека.

## Клавиши

Матрица 3 x 5 сканируется раз в миллисекунду с ранним debounce: изменение принимается, как только два подряд опроса совпали (1-2 мс после замыкания контакта), после чего следующие 8 мс изменения этой клавиши игнорируются. В HID-битовой карте бит `row * 5 + column` соответствует физической кнопке, начиная с верхней левой. Нажатие устанавливает бит, отпускание очищает его. Удержание передаётся сохранением установленного бита; жесты хост определяет самостоятельно.

Пауза переключения строк задаётся ограниченным числом инструкций. `platform_delay_ms()` использует программную задержку относительно частоты ядра и не является независимым калиброванным таймером. Для времени протокола и debounce используется `timebase`.

## Дисплей

Нативная геометрия панели: 480 x 854. Физическое направление связано с нативными координатами формулой `x = v`, `y = 853 - u`, где `u` направлено вправо на устройстве, `v` вниз.

Окна кнопок имеют размер 103 x 103. Боковая область в нативных координатах: `x=35`, `y=10`, `width=406`, `height=85`. Полная карта находится в `layout.json`.

Штатный режим вывода использует DMA, глубину CPU-пути 2 и 16-битный цвет. Промежуточные буферы: два по 1440 байт, выравнивание 4. При тайм-ауте DMA драйвер прекращает DMA-передачу и переходит на CPU-путь до перезапуска.

Пиксели BLIT идут по SPI 16-битными кадрами: прошивка меняет байты пикселей местами в промежуточном буфере перед DMA. Команды и регистры контроллера передаются 8-битными кадрами, после BLIT SPI возвращается в 8-битный режим. Режим переключается feature report 4. Пока DMA передаёт буфер, прошивка не ждёт его и продолжает принимать USB; отчёт остаётся в очереди, пока его пиксели не переданы. Ждёт DMA только последний буфер BLIT.

Пропускная способность полноэкранного BLIT на плате: около 3,8 МБ/с, предел задаёт SPI. Делитель SPI уже минимальный.

Начальные регистровые последовательности, порядок volatile-доступов и коэффициенты задержек сохраняются при обычном рефакторинге. Изменение этих параметров требует отдельной проверки на плате.

## USB

OUT endpoint `0x01` использует двойную буферизацию FIFO: пока прошивка читает один пакет, хост передаёт следующий. FIFO читается 32-битными словами прямо в слот очереди отчётов, без промежуточной копии.

## Видеопамять

Контроллер дисплея имеет 16 МБ SDRAM.

| Область | Назначение |
| --- | --- |
| `0x000000` | Экран, canvas 0 |
| `0x100000..0xAD7FFF` | Кэш страниц приложения: 21 страница 480 x 512 по `0x78000` байт |
| `0xB00000..0xBC827F` | Промежуточный кадр приложения для копирования по VSYNC |
| `0xC00000..0xCC827F` | Кадр новой страницы для TRANSITION, заполняет приложение |
| `0xD00000..0xDC827F`, `0xE00000..0xEC827F` | Два кадра, которые прошивка показывает по очереди во время TRANSITION |
| `0x400000..0x52C3FF`, `0x600000..0x72C3FF` | Заставка и игра до перехода к экрану приложения |

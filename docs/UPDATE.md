# Обновление прошивки

Прошивка записывается через штатный загрузчик деки (`LT32U03_CTP_bootlader_V1_0`), который лежит во flash `0x08000000..0x08003FFF`. Загрузчик в образ не входит и обновлением не затрагивается: запись идёт только в область приложения `0x08004000..0x0801B8EF` (96 496 байт).

Прошивальщик: `open-stream-deck-app/src-tauri/src/firmware.rs`.

## Вход в загрузчик

| Состояние деки | Способ |
| --- | --- |
| Open Stream Deck | Команда OSD1 `0A BOOT` с сигнатурой `OSDBOOT!`. Поддержка объявляется битом 0 байта 17 Feature report 3 |
| Штатная прошивка AJAZZ (`0300:1020`) | Output report 512 байт: `CRT`, два нулевых байта, `APPNEW` |
| Замкнуты два контакта на плате при подключении USB | Загрузчик остаётся сам |

Обе программные команды делают одно и то же. Через ROM-API flash (init `0x04005C51`, стирание `0x04005AF5`, запись слова `0x04005ACD`, ключ `0x9786AC03` в `0x40003804`) переписывается сектор `0x0807E000`: слова 0 и 2 сохраняются, слова 1 и 3 инвертируются, по `0x0807E010` пишется маркер `0x21436587`. Затем выполняется сброс битом 31 регистра `0x40002000`.

Загрузчик остаётся в режиме прошивки, если выполнено любое условие:

- замкнут контакт (`0x4001D000`, бит 0);
- по `0x0807E010` лежит маркер `0x21436587`;
- в RAM по `0x20028000` лежат слова `0x32021688`, `0x19714568` (загрузчик их стирает);
- вектор сброса приложения равен `0xFFFFFFFF`.

## Протокол загрузчика

HID `EEEF:2929`, отчёты по 64 байта без Report ID. На каждую команду D* загрузчик отвечает 64 байтами, в байте 3 повторяет код команды.

| Код | Байты 0..2 | Байт 3 | Далее | Действие |
| --- | --- | --- | --- | --- |
| D2 | 0 | `D2` | смещение `u32`, размер в байтах `u32` | стирание области по 512 байт |
| D1 | смещение, 24 бита | `D1` | 60 байт данных | запись 15 слов, хвост дополняется `FF` |
| D3 | 0 | `D3` | число слов `u32`, CRC `u32` | проверка CRC-16/ARC по записанному образу |
| AA | 0 | `AA` | `02` | переход в приложение без ответа |

После успешной D3 загрузчик записывает в сектор `0x0807E000` CRC, `~CRC`, число слов, `~число слов` и стирает маркер.

## Перезапуск после записи

По `AA` загрузчик сразу прыгает на вектор сброса приложения, без сброса чипа.

- Вход контактами (до этого было включение питания): приложение стартует само.
- Вход программно: ни эта прошивка, ни штатная после прыжка не стартуют, нужно переподключить USB. Приложение просит об этом и ждёт деку до 3 минут.

## Особенности тёплого старта

- Watchdog `0x40005000` переживает программный сброс. Загрузчик его не включает, но кормит. Поэтому прошивка кормит watchdog с первой инструкции `Reset_Handler` и во время настройки тактирования.
- Служебная область flash `0x082000xx` читается только после включения питания; после тёплого сброса чтение вызывает сбой. `platform_init` читает `0x082000A4` и `0x082000C8` через пробу: обработчик сбоя пропускает инструкцию, а значения берутся из кэша в `.noinit`, который переживает тёплый сброс, или из запасных констант.

# Протокол OSD1 v1

## USB HID

| Параметр | Значение |
| --- | --- |
| VID:PID | `1209:0001` |
| bcdDevice | `0200` |
| Manufacturer | `Open Stream Deck` |
| Product | `OSD AKP153R` |
| Serial | `OSD153R00001` |
| Input | Report ID 1, 19 байт |
| Output | Report ID 2, 1024 байта |
| Feature | Report ID 3, 4, `0x7D`, `0x7E` и `0x7F`, по 32 байта |
| IN endpoint | `0x82` |
| OUT endpoint | `0x01` |

Размеры report включают байт Report ID. Размер USB-пакета: 64 байта в Full Speed и 512 в High Speed. Один HID report может передаваться несколькими пакетами.

## Output report

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 1 | `2` |
| 1 | 2 | Длина полезных данных, little endian |
| 3 | До 1021 | Поток команд |

Бит 15 поля длины означает SYNC: parser сбрасывает предыдущую незавершённую команду/BLIT и начинает новую команду с первого байта payload. Этот бит исключается из значения длины. После любой ошибки протокола parser отбрасывает payload всех report до ближайшего report с SYNC, чтобы остаток оборванного изображения не разбирался как команды.

Payload нескольких report образует непрерывный поток. Команда, аргументы и пиксельные данные могут пересекать границы report. Все многобайтные числа передаются little endian.

## Команды

| Opcode | Команда | Аргументы |
| --- | --- | --- |
| `00` | NOP | Нет |
| `01` | CANVAS | `address:u32` |
| `02` | BLIT | `x:u16 y:u16 width:u16 height:u16`, затем `width*height*2` байт RGB565 |
| `03` | FILL | `x:u16 y:u16 width:u16 height:u16 color:u16` |
| `04` | LINE | `x0:u16 y0:u16 x1:u16 y1:u16 color:u16` |
| `05` | CIRCLE | `x:u16 y:u16 radius:u16 color:u16 fill:u8` |
| `06` | FRAME | `x:u16 y:u16 width:u16 height:u16 color:u16` |
| `07` | COPY | `source:u32 sx:u16 sy:u16 destination:u32 dx:u16 dy:u16 width:u16 height:u16` |
| `08` | BRIGHT | `percent:u8`, ограничивается диапазоном 0..100 |
| `09` | FENCE | `id:u32` |
| `0A` | BOOT | `magic:8` = ASCII `OSDBOOT!`; перезапуск в штатный загрузчик `EEEF:2929` |
| `0C` | VSYNC | Нет |
| `0D` | BLEND | `s0:u32 s0x:u16 s0y:u16 s1:u32 s1x:u16 s1y:u16 destination:u32 dx:u16 dy:u16 width:u16 height:u16 alpha:u8` |
| `0E` | TRANSITION | `next:u32 effect:u8 duration:u16 ox:u16 oy:u16` |

Canvas 0 соответствует экрану. Координаты нативные, ширина canvas 480 пикселей. BLIT использует построчный RGB565. FRAME рисует контур толщиной один пиксель. COPY копирует область между canvas через BTE. BLEND смешивает две области через BTE: `S0 * (32 - alpha) / 32 + S1 * alpha / 32`, alpha ограничивается диапазоном 0..32.

TRANSITION плавно переводит 15 клавиш и три секции боковой полосы (`38,10`, `187,10`, `336,10`, по 103 x 85) с canvas 0 на canvas `next`, где новая страница уже лежит в тех же координатах, что и на экране. Effect 0 копирует ячейки сразу, effect 1 запускает волну: в каждой ячейке за 60% `duration` от центра к краям раскрывается прямоугольник новой страницы с пропорциями ячейки, с задержкой, пропорциональной расстоянию от центра ячейки до точки `ox, oy`. Используется только COPY, поэтому цвета не искажаются. Кадры собираются в `0xD00000` и `0xE00000` и выводятся сменой адреса отображения по VSYNC, поэтому канал USB во время перехода не используется. Пока переход идёт, parser не берёт следующие команды; FENCE после TRANSITION сообщает об окончании. В конце ячейки копируются в canvas 0 и экран снова показывает canvas 0. Во время заставки TRANSITION работает как effect 0.

Очередь содержит 24 слота, из которых доступно 23. Основной цикл обрабатывает до четырёх report за проход. При отсутствии прогресса пиксельного потока более 1000 мс parser сбрасывается, это считается ошибкой с причиной 7.

Когда компьютер переводит USB в suspend, прошивка гасит подсветку и запоминает яркость. На resume или сброс шины яркость возвращается. BRIGHT во время suspend только запоминается.

VSYNC ждёт начала следующего кадра панели по флагу VSYNC контроллера (REG 0Ch, bit4), не дольше 40 мс. Хост ставит её перед копированием готовых изображений в canvas 0, чтобы обновление не разрывалось посреди развёртки. Если флаг не пришёл за 40 мс, прошивка до перезапуска дисплея выполняет VSYNC без ожидания.

FENCE возвращает идентификатор последней обработанной команды в Input report. Для нового изображения хост должен передавать полную последовательность команд, а не полагаться на восстановление оборванного потока.

## Input report

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 1 | `1` |
| 1 | 2 | Битовая карта 15 клавиш |
| 3 | 1 | Счётчик изменений клавиш, modulo 256 |
| 4 | 4 | Последний FENCE ID |
| 8 | 1 | Счётчик ошибок потока modulo 256. Хост, увидев изменение, прекращает ждать FENCE текущего изображения и начинает новое с SYNC |
| 9..18 | 10 | Нули |

Report отправляется при изменении состояния клавиш, FENCE, счётчика ошибок и после новой USB-конфигурации. Бит 0 соответствует верхней левой кнопке, бит 14 нижней правой.

## Feature report 4

Чтение:

| Смещение | Значение |
| --- | --- |
| 1..4 | Частота ядра, Гц |
| 5 | 1, если время считается через DWT |
| 6 | 1, если пиксели BLIT идут 16-битными кадрами SPI |
| 7 | `0` |
| 8..23 | Регистры SPI `0x40011000..0x4001100F`, регистр данных читается как 0 |
| 24..27 | Такты ядра, пока DMA передавал данные SPI |
| 28..31 | Байты, переданные по SPI |

Запись: байт 1 включает (`1`) или выключает (`0`) 16-битные кадры SPI для следующих BLIT. По умолчанию 16-битные кадры включены.

| 30..31 | Худшее время сборки кадра TRANSITION в микросекундах, `u16` |

## Feature report `0x7F`

Запись с ASCII `OSDBOOT!` в байтах 1..8 перезапускает деку в штатный загрузчик, как команда BOOT. Запрос идёт через EP0 и работает, даже если поток Output report недоступен.

## Анимация запуска

После включения прошивка показывает анимацию из отдельного буфера SDRAM по адресу `0x600000`: регистр начала отображаемого изображения указывает на этот буфер, а canvas 0 продолжает принимать команды хоста. Хост рисует первый кадр как обычно и не ждёт окончания анимации.

1. Ячейки 6 × 3 (5 столбцов клавиш и 3 секции боковой полосы) заливаются цветом `#222222` змейкой: верхний ряд слева направо, средний справа налево, нижний слева направо.
2. Шрифтом Inter SemiBold побуквенно проявляются OPEN (ячейки 1-4), STREAM (ячейки 7-12) и DECK (ячейки 13-16); ячейки нумеруются слева направо, сверху вниз.
3. Первое рисование хоста в canvas 0 (BLIT, FILL, FRAME, LINE, CIRCLE при текущем canvas 0, COPY или BLEND с destination 0, TRANSITION) считается готовностью. С этого момента оставшееся проявление идёт в 4 раза быстрее. После завершения проявления и паузы 150 мс ячейки той же змейкой раскрываются из центра, показывая содержимое canvas 0 поверх неподвижной надписи.
4. Отображение переключается на canvas 0, буфер `0x600000` больше не используется.

Пока идёт анимация, parser в момент очередного кадра (каждые 15 мс) останавливается на ближайшей границе команд: текущий BLIT дописывается до конца, следующая команда ждёт, пока кадр анимации будет нарисован. Поток хоста не теряется, а анимация не замирает во время заливки страниц.

Без хоста заставка остаётся на экране; новое нажатие кнопки запускает игру. Игра использует промежуточный canvas `0x400000`. До завершения перехода к экрану приложения хост не должен использовать SDRAM `0x400000..0x52C3FF` и `0x600000..0x72C3FF`.
